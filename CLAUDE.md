# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Key constraint: no npm on the host

No Node.js/npm on host. All build/install commands run inside Docker:

```bash
# Build and start (primary workflow)
docker compose up --build -d

# Run arbitrary npm/node commands
docker run --rm -v /home/igor/gantt-editor2:/work node:20-alpine sh -c "cd /work && <command>"

# Example: add a package
docker run --rm -v /home/igor/gantt-editor2:/work node:20-alpine sh -c "cd /work && npm install <pkg>"

# Type-check only (no emit)
docker run --rm -v /home/igor/gantt-editor2:/work node:20-alpine sh -c "cd /work && npx tsc --noEmit"

# Unit tests (vitest; pure modules in src/lib/*.test.ts). The script pins
# TZ=Europe/Warsaw so the DST cases in the date / workload tests are real.
docker run --rm -v /home/igor/gantt-editor2:/work node:20-alpine sh -c "cd /work && npm test"
```

App served at **http://localhost:3000**.

## Architecture

React 18 + TypeScript + Vite frontend, static files via nginx, multi-stage Docker build.

**Split-panel layout** (`App.tsx`): left panel (task list) + right panel (Gantt chart) split by draggable `Divider`. Panel widths stored as percentage (15–70%).

**Views** (`src/hooks/useHashRoute.ts`): header switch `Board | Portfolio`, hash routed (`#/` board, `#/portfolio/{overview|roadmap|gantt|workload|people}`), no router dependency. The board body (TaskPanel / GanttPanel / strip) unmounts in portfolio view; on return GanttPanel re-inits and re-wires scroll sync through `onContainerReady`.

**Core types** (`src/types.ts`): `GanttTask` has `id`, `name`, `type?: 'task' | 'milestone'` (absent means task — see Milestones section), `start?: Date`, `end?: Date` (both optional — a task without dates is valid and shown only in the left panel), `progress: number` (in data model, not shown in chart), `dependencies?: string[]` (predecessor *local* ids), `parentId?: string` / `remoteParent?: string | null` (see Subtasks section), `clickupId?: string` (set when task linked to ClickUp), and ClickUp-synced optional fields: `status?: string`, `priority?: 1|2|3|4`, `assignees?: Assignee[]`, `tags?: Tag[]`, `description?: string`. Pull-only from ClickUp (never pushed): `statusType?: string` (`status.type`: open / custom / closed / done) and `timeEstimate?: number` (ms). `syncBase?: SyncBase` = field fingerprints agreed at the last pull / push (see ClickUp pull / push, Conflicts). `Assignee` is `{ id: number; username: string }` — stores ClickUp user ID (needed to push assignee changes via API). Migrated tasks from old `string[]` format get `id: -1` as sentinel; those are display-only and excluded from ClickUp pushes. `Tag` is `{ name: string; tag_bg?: string; tag_fg?: string }`.

**State and persistence** (`src/hooks/useTasks.ts`): all tasks in single `useState` array, persisted to `localStorage` under key `'gantt-tasks'`. First load creates example task. `updateTask` uses functional `setState` form so sequential calls compose correctly (React 18 batches). `deserialize` runs a migration on load: if `assignees` entries are strings (old format), they're wrapped as `{ id: -1, username }`; absent `start`/`end` fields deserialize to `undefined` (not Invalid Date).

**Gantt library** (`src/lib/frappe-gantt/`): frappe-gantt vendored locally (not npm) for free modification. Vite alias `frappe-gantt` → `src/lib/frappe-gantt/index.js` keeps imports unchanged. `@types/frappe-gantt` stays in devDependencies for types.

Local fork changes:
- `get_all_dependent_tasks()` BFS — original prematurely added nodes to `out` before computing `to_process`, limiting traversal to one level. Fixed with `Set`-based BFS.
- `bind_bar_events` — dependents included in drag group during resize. Fixed: only include dependents when `is_dragging` true.
- `_placeholder` task support (see Dateless tasks section below).
- `milestone.js` (new file) + `make_bars` dispatch on `_milestone` (see Milestones section below).
- Subtasks: `get_all_dependent_tasks` also follows a task's `_drag_with` ids (its subtasks), so they move live with a dragged parent; the mousedown drag group filters ids without a bar; `Bar.draw_span()` draws `rect.bar-span` under a bar when `task._span = { start, end }` is set, shifted in `update_bar_position`; `update_bar_position` skips predecessors without a bar (it dereferenced `get_bar(dep).$bar` unguarded).
- `Bar.compute_start_end_date()` / `Milestone.compute_start_end_date()` `Math.round` the unit counts before `date_utils.add`, which `parseInt`s: Week view float math gives e.g. 60.99999 for day 61, so a dropped bar landed a day early.
- `Bar.refresh()` rewrites the group's `class` attribute wholesale instead of `classList.add(custom_class)`. The original threw `InvalidCharacterError` on a multi-token `custom_class` (`'milestone critical'`) and never dropped a token removed since the last refresh.
- `week_start` option (`defaults.js`, `Date.getDay()` numbering, default 1 = Monday): `setup_gantt_dates` snaps `gantt_start` back to it in Week view (`unit === 'day' && step === 7`), so week columns start on that weekday. Originally they started wherever the padding landed. The mousewheel extender of the infinite padding grows by `extend_by_units * step` units (whole columns) instead of `extend_by_units` days, which keeps that alignment and makes its scroll compensation (`column_width * extend_by_units`) match the columns actually added.

**Alignment constants** (`src/constants.ts`): frappe-gantt row/header geometry hardcoded in library. `GANTT_ROW_HEIGHT` (48px) and `GANTT_HEADER_HEIGHT` (85px) must stay in sync with frappe-gantt defaults. LHS `TaskPanel` header height = `GANTT_HEADER_HEIGHT + GANTT_TOOLBAR_HEIGHT` to account for toolbar above gantt.

**Scroll sync** (`App.tsx` `handleContainerReady`): bidirectional scroll sync between `.gantt-container` div (RHS) and task list div (LHS) via event listeners guarded by `isSyncingRef` to prevent feedback loops. Sync is pixel-based (`scrollTop`), so both panels must always have the same number of rows — enforced by placeholder rows (see below).

**Dependency propagation** (`src/utils.ts`, `GanttPanel.tsx`, `App.tsx`):
- `getAllSuccessors(taskId, tasks)` — shared BFS, returns all transitive successors.
- Stored dates carry mixed times of day (LHS pickers: local midnight; frappe drag/resize: start 00:00, end 23:59:59; ClickUp: e.g. 4 am), so everything here works in **whole local calendar days**: `daysBetween` to compare, `shiftDays` (`src/lib/dates.ts`, keeps the time of day) to move. Never raw ms deltas, which break across DST and between a 23:59:59 and a midnight end. Dates go to frappe as the local day (`isoDay`), never `toISOString` (UTC day, one off for local midnight east of UTC).
- `GanttPanel` `on_date_change`: drag = start and end moved by the same days → shifts `dragClosure` (successors + subtasks, transitively); right-edge resize (start unchanged) → shifts successors only by the end's days; left-edge resize → propagates nothing. Lookups go through `allTasks`, so collapsed / filtered-out rows move too. Guards skip tasks with undefined dates.
- `App.handleTaskUpdate`: LHS end date change shifts all transitive successors by the end's day delta. Guards skip tasks with undefined dates.

**Connect mode** (`GanttPanel.tsx`): click-to-connect for creating/removing dependency arrows. Uses `ganttClickRef` reassigned every render so frappe-gantt's `on_click` always has fresh closure. `connectModeRef`/`connectSourceRef` are refs (not state) for frappe-gantt callbacks; `connectMode`/`connectSource` are state for React re-renders. Escape cancels connect mode.

**Refresh without scroll reset** (`GanttPanel.tsx`): every `gantt.refresh()` saves and restores `.gantt-container` scroll position to prevent jumping on React re-renders.

**Chart height** (`GanttPanel.tsx`): frappe-gantt's container height is set at init; a `ResizeObserver` on `.gantt-panel__chart` keeps `$container.style.height` and `options.container_height` matching the panel afterwards (window resize, workload strip toggled).

**Board workload strip** (`components/WorkloadStrip.tsx`): "▤ Workload" in the gantt topbar, persisted to `localStorage['gantt-load-strip']` as `{ on, metric }`. Mounted in `App.tsx` *below `app__body`, full width*, so both panels lose the same height and the pixel scroll sync stays aligned. Buckets are frappe-gantt's own columns: `GanttPanel` reports `{ dates: gantt.dates, columnWidth }` via `onGeometry` after init / refresh and on container scroll (infinite padding re-renders with more columns from inside frappe's wheel handler); the strip measures the `.gantt-container` rect to line up its plot and mirrors `scrollLeft` with a CSS transform (no re-render). Uses `filteredTasks`, so it follows the filters (and the workload backlog setting on top).

**TaskRow** (`components/TaskRow.tsx`): takes a `TreeRow` (see Subtasks): indent, collapse toggle, `done/total` subtask badge, `⋯` row menu (fixed-position so the list's scroll box can't clip it; Delete lives there, no separate ✕, to leave the name column room). Inline name editing (click to edit, Enter/Blur to commit, Escape to cancel). Overdue tasks (`isOverdue` from `lib/portfolio.ts`) get `.task-row--overdue`: the due date (always the last date field) turns red and its title says how many days late. FilterBar has a matching `overdue` filter type. Date inputs show empty when date is undefined; clearing the text field (blur on empty) sets the date to `undefined`. Clamping (start > end prevention) only runs when both dates are defined. Row height fixed to `GANTT_ROW_HEIGHT` for gantt alignment. `⤢` icon button (visible on hover) opens `TaskDetailPopup`.

**TaskDetailPopup** (`components/TaskDetailPopup.tsx`): centered modal opened from the `⤢` button on each task row. State in `App.tsx` (`detailTaskId`). Shows: task ID badge, status selector (editable when ClickUp configured), ↗ link to ClickUp if `clickupId` set, priority pill dropdown (1=Urgent/2=High/3=Normal/4=Low), editable name, assignee chips with `×` remove + `+ Add` button (when ClickUp configured), tag chips with `×` remove + `+ Add tag` button (when ClickUp space configured), date pickers (empty when undefined; clearing sets to undefined), dependency chips with `×` remove, description textarea. Days display only shown when both dates are defined.

**StatusSelector** (inline component in `TaskDetailPopup.tsx`): colored badge in the topbar that opens a dropdown of list statuses when ClickUp token + listId are configured. Fetches available statuses via `getListStatuses` on first open and caches them for the popup's lifetime. Picking a status patches `status`, `statusColor` and `statusType` together.

**AssigneePicker** (`components/AssigneePicker.tsx`): floating dropdown rendered inside the assignees row of `TaskDetailPopup`. Fetches workspace members via `listTeamMembers` on first open (cached in component state for the popup's lifetime). Fuzzy-filters by username+email substring.

**TagPicker** (`components/TagPicker.tsx`): floating dropdown in `TaskDetailPopup`. Fetches space tags via `getSpaceTags` on first open. Shows existing tags with toggle checkmarks; supports creating new tags inline. Only visible when ClickUp token + spaceId are configured.

**CSS** (`src/App.css`): CSS custom properties defined in `:root` at top of file — `--accent`, `--border`, `--surface-*`, `--text-*`, `--radius-*`, `--shadow-*`. All popup styles use these vars. Existing non-popup styles use hardcoded colors for historical reasons.

## Settings

"Settings" header button, `components/SettingsDialog.tsx` (edits a draft; Save / Cancel / Reset to defaults). Model and rules in `src/lib/settings.ts` (pure), state in `src/hooks/useSettings.ts` (`localStorage['gantt-settings']`, read through `normalizeSettings`, which validates field by field so old or partial values get defaults). App passes `settings` down as a prop (no context). **Defaults reproduce the behaviour from before settings existed.**

- `warnings`: `emptyDescription` (on), `missingDod` (on), `missingPriority` (off), `dodKeywords` (`DoD`, `Definition of Done`; never empty). `dodPattern` matches whole phrases, case-insensitive, with Unicode-aware boundaries (`\b` is ASCII-only), memoized on the keyword list. `warnings.ts`: `contentWarningIds` (description facts: `empty-description`, which also implies no DoD, or `missing-dod`), `applyWarningSettings(ids, task, settings)` (toggles + priority + backlog), `getTaskWarnings(task, settings)` = both, used by `TaskRow`.
- `calendar: { weekStart, workdays }` (`Date.getDay()` numbers; Monday, Mon-Fri; at least one workday). `dates.ts`: `startOfWeek(d, weekStart)`, `unitStarts` / `unitBoundaries(..., weekStart)`, `isWorkday(d, workdays)`, all defaulting to the old Monday / Mon-Fri. Used by the live gantt (fork `week_start` + `is_weekend`; `GanttPanel` re-renders in place on change via `change_view_mode(_, true)`, not `update_options`, which would reset `container_height`), the export, the portfolio week buckets, hours spread and capacity. `workdayLabel` replaces the old hard-coded "Mon-Fri" texts.
- `backlog: { statuses, include: { board, warnings, health, workload } }`: a task is backlog when its trimmed status equals a listed name, case-insensitive (default `backlog`; may be empty). `withoutBacklog(tasks, settings, area)` returns the input unchanged when backlog is included there. `board`: rows + gantt bars (through the `include` set above); `warnings`: row warnings and portfolio quality; `health`: RAG, KPIs, risk list, roadmap RAG outline; `workload`: Workload / People tabs and the board strip. Pull / push always see every task.
- `rules: { dueSoonDays, redOverdueShare, amberUnscheduledShare }` (7, 0.2, 0.25), clamped by `normalizeSettings`.

## Dateless tasks

Tasks without `start`/`end` are valid and appear in the left panel like any other task, but are not rendered as bars in the Gantt chart. Dependency arrows involving a dateless task also do not appear.

**Scroll sync preservation**: frappe-gantt must always render exactly N rows (one per task, in order) for the pixel-based scroll sync to stay aligned. To achieve this, `GanttPanel` passes ALL tasks to frappe-gantt, marking dateless tasks with `_placeholder: true`. The vendored frappe-gantt handles `_placeholder` tasks as follows:
- `setup_tasks`: placeholder tasks skip date validation; `_start`/`_end` are set to `new Date()` (dummy, never used for display)
- `setup_gantt_dates`: placeholder tasks are skipped when computing the visible date range; if all tasks are placeholders, falls back to today
- `make_bars`: bar group for placeholder tasks gets `visibility:hidden; pointer-events:none`
- `make_arrows`: arrows are skipped when either endpoint task has `_placeholder: true`

## Subtasks

**Model** (`src/types.ts`): `parentId?: string` (local id of the parent) and `remoteParent?: string | null` (ClickUp parent id at the last sync; `null` = top level; absent = never synced with hierarchy, e.g. data from before subtasks). The array stays flat: **array order is sibling order** and the display order is derived, so no operation keeps subtrees contiguous. A `parentId` naming no task, or leading into a cycle, makes the task a root.

**`src/lib/tree.ts`** (pure, tested): `buildTree` (roots / children / effective parent), `descendants`, `ancestors`, `flattenTree(tasks, { collapsed, include })` -> `TreeRow { task, depth, childCount, doneChildren, collapsed, context }`, `subtreeSpan`, `dragClosure`, `selectionDepths`, and the moves `moveTask(tasks, id, targetId, 'before' | 'after' | 'inside' | 'inside-first')`, `setParent`, `indentTask` (previous sibling becomes parent), `outdentTask` (sibling right after the old parent), `removeSubtree`. `moveTarget` validates a move (not into its own subtree; not to the top level when `!canBecomeTopLevel`); invalid moves return the input array unchanged. `useTasks` wraps them; `removeTask` deletes the whole subtree (App confirms when there are subtasks) and, when it holds a linked task, records a pending deletion (see Deleting tasks).

**Board** (`App.tsx`): `rows = flattenTree(tasks, { collapsed, include })` and `visibleTasks` go to **both** panels, so the pixel scroll sync stays aligned. Collapse state is UI only, `localStorage['gantt-collapsed']` (string[]). While filtering or hiding the backlog (Settings), `include` = the shown tasks and their ancestors appear as muted `context` rows, always expanded; `filteredTasks` (matches only, from `boardTasks` = tasks minus a hidden backlog) still drives the FilterBar count, critical-path view scope and the workload strip. LHS: `⋯` menu (add subtask, indent, outdent, make top-level, delete), Tab / Shift+Tab while renaming, id-based drag and drop (top quarter before, bottom quarter after or first child of an expanded parent, middle = nest; the indicator is indented to the landing level), Expand / Collapse all. Popup: Parent row (`ParentPicker`, excludes self + own subtree), Subtasks section (open, + Add subtask, Fit dates to subtasks). A new subtask goes through the draft popup with `parentId` set and the parent's dates.

**Gantt**: a parent's own dates stay independent (as in ClickUp). `GanttPanel` gets `allTasks` + `rows`; per bar it sets `custom_class` tokens `parent` / `context` (next to `milestone` / `critical`), `_span` (subtree span, including hidden subtasks) and `_drag_with` (subtasks with bars). Dependencies handed to frappe are filtered to visible ids with a bar. Colors: `--g-parent-color`, `--g-span-color` (gantt `themes.css`, light + dark).

**ClickUp limit**: the API moves a subtask to another parent (`PUT /task/{id} { parent }`) and creates subtasks (`parent` in the create body, same list), but rejects `parent: null`. So a task that is a subtask in ClickUp (`clickupId && remoteParent`) can never be made top level here: `canBecomeTopLevel` gates every UI path, with `TOP_LEVEL_BLOCKED` as the explanation.

**Elsewhere**: workload count metric skips tasks with eligible subtasks (no double count); hours keep a parent's own estimate (API estimates are per task, never rolled up) and never flag an estimate-less parent as missing. Portfolio health / risks do not flag a task with subtasks as undated or unassigned (`parentIdsOf`). Portfolio tasks carry `parentId` (ClickUp ids there) and `parentName` (shown as a breadcrumb by `TaskName`); Roadmap has a "Subtasks" toggle (off = top level with a span line under parents). Export keeps board order and indents the name column by `ExportOptions.depths`. Critical path ignores hierarchy (it is not a dependency).

## Milestones

`type: 'milestone'` marks a zero-duration task (ClickUp custom task type id 1). A milestone keeps **one date in both `start` and `end`**; every writer keeps them equal. A dateless milestone is legal and follows the `_placeholder` path above.

- **Conversion** (`src/utils.ts`): `isMilestone(t)` and `typeChangePatch(t, next)`. Task → milestone keeps the **due date** (`end ?? start`); milestone → task leaves a one-day task.
- **UI**: `TypePill` in `TaskDetailPopup`'s hero (also the create path — the "+ Add task" draft popup); `TaskRow` shows a `◆` glyph and a single date picker, with a hidden `.task-row__date-ghost` stand-in so the date stays in the due-date column.
- **Rendering**: `GanttPanel` maps a dated milestone with `_milestone: true` and `custom_class: 'milestone'`. `make_bars` builds a `Milestone` (`src/lib/frappe-gantt/milestone.js`) instead of a `Bar`. `$bar` stays a `<rect>` (arrows, drag cache and `compute_start_end_date` read x/y/width/height attributes) sized `28 / √2` square, centred on the day cell; CSS rotates it 45° with `transform-box: fill-box` so no JS maintains a transform during drags. The subclass also drops the resize handles (and stubs `update_handle_position`, which the base dereferences unguarded every drag frame), pins `duration` to one day, and reports `date_change` with the same date twice instead of end − 1s.
- **Colors**: `--g-milestone-color` (gantt `styles/themes.css`, light + dark) and `--milestone` (`src/App.css`, used by the left-panel glyph and the popup pill).

## Critical path

`src/lib/criticalPath.ts` — `computeCriticalPath(tasks)` returns `{ taskIds: Set<string>, edges: Set<string> }`, edges keyed `` `${predecessorId}->${successorId}` `` by the exported `edgeKey`. `EMPTY_CRITICAL` is a module const so the empty case keeps a stable identity for `useMemo` / effect dep arrays.

**Definition: longest dependency chain**, weighted by task duration, gaps between bars ignored. *Not* zero-slack CPM — dates here are hand-set, so a slack rule would drop tasks from the chain merely because the user left room between two bars. Duration is inclusive days (`end − start + 1`), milestones count 0. Only tasks with both dates are nodes; a dateless task breaks the chain, matching the fact that it has no bar and no arrows.

Two memoized walks: `chainTo` (longest chain ending at a node, over predecessors) and `chainFrom` (longest chain starting at it, over successors, using an inverted index — not `getAllSuccessors`). `maxTotal` is the max of `chainTo` over nodes that *have* a predecessor, so a lone long task is never reported as the path. A node is critical when `chainTo + chainFrom − duration === maxTotal`; an edge is critical when both ends are and `chainTo(from) + chainFrom(to) === maxTotal`. Tied chains are all kept. Both walks are cycle-safe (a back edge inside an in-progress walk contributes 0); a pure cycle yields the empty result rather than hanging.

**Two toggles**, both persisted to `localStorage['gantt-critical']` as `{ on, scope }`, state in `App.tsx`, controls rendered in the `GanttPanel` topbar: on/off, plus scope `'project'` (compute over all `tasks`) vs `'view'` (over `filteredTasks`). `ExportDialog` has its own equivalent pair in `localStorage['gantt-export-opts']` (`highlightCritical`, `critScope: 'project' | 'export'`).

**Styling is red outline, fill preserved**, so ClickUp status colors survive. Live chart: `GanttPanel` appends a `critical` token to `custom_class` (hence the `Bar.refresh()` fork fix above) and `App.css` strokes `.bar-wrapper.critical .bar` with `!important`, since gantt.css pins `stroke-width: 0`. Arrows carry no class, so `applyCriticalArrows()` re-marks `path[data-from][data-to]` after every init/refresh — arrows are rebuilt each refresh. Left panel gets `.task-row--critical` (inset box-shadow, so row height stays 48px). Color lives in `--critical` (`App.css`) and `C.critical` (`exportGantt.ts`), which must stay in sync.

Export: `ExportOptions.criticalIds` / `.criticalEdges` are precomputed by `ExportDialog` over the **whole** selection and passed down — never computed inside `buildGanttSvg`, which receives row slices per page and would otherwise produce a different path on every page.

## Export to PNG / PDF

"Export" button in the app header opens `ExportDialog`. The exported picture is **redrawn from the task array**, never screenshotted from the live chart — the on-screen gantt mixes SVG bars with absolutely positioned HTML header divs and is clipped by `.gantt-container`'s scroll box. No new dependencies.

**Renderer** (`src/lib/exportGantt.ts`): `buildGanttSvg(rows, opts)` is pure, returns `{ body, width, height }`; `svgDocument(built, size?)` wraps it in an `<svg>` root. Left columns (`COLUMNS`/`COLUMN_ORDER`, `name` always present) then a timeline: two-band date header, unit grid, non-working day shading (day view, `ExportOptions.calendar`), bars/milestone diamonds, dependency arrows, today marker (`ExportOptions.today`, default now).
- **Rows** are `ExportRow = { kind: 'task', task } | { kind: 'section', section, cont? }`; the board wraps its tasks with `taskRows`. A section row (`SECTION_H` 32 vs `ROW_H` 26, `rowHeight`) is an opaque band in a tint of the project color, drawn over the grid, inside `<g data-section="id">`: swatch, name (`(cont.)` when repeated at a page top), task count, and in the timeline a summary bar (`span`, done share solid, milestone diamonds, `NN%`). Its summary is precomputed by the caller over the whole project. `sectionToggles` adds the ▾ / ▸ glyph and `cursor="pointer"` (on-screen only). Row banding restarts under each section. `rowsWindow` = `fitWindow` over task rows plus section spans.
- Ids must be unique across the rows (arrows, critical path, depths key by id): the portfolio qualifies them.
- **Self-contained by necessity**: colors are hardcoded literals (copied from `src/App.css` `:root` and gantt `themes.css`) and the font is `Helvetica, Arial, sans-serif`. Once the SVG is detached from the document — or loaded through `<img>` for rasterization — `var()` cannot resolve and external fonts cannot load. The root always carries explicit `width`/`height`; Firefox has no intrinsic size otherwise.
- **Time mapping** is one linear `pxPerDay` scale, but grid lines are drawn at *real* unit boundaries, so month columns are naturally 28–31 days wide with no drift. `daysBetween` rounds so DST never shifts a day. The calendar helpers (`startOfDay`, `addDays`, `daysBetween`, `startOfWeek`, `unitStarts`, `autoUnit`, ...) live in `src/lib/dates.ts`; `exportGantt.ts` re-exports the ones it used to export.
- Bars are clamped to the window; a clipped edge gets a white chevron so truncation is visible. Dateless rows render their LHS cells plus a muted `no dates` label.
- Arrows are ported from `src/lib/frappe-gantt/arrow.js:13-89` with export geometry substituted for `gantt.options.padding` / `header_height`.
- SVG has no text-overflow: `fitText` truncates with a real ellipsis, measuring through a module-level canvas 2D context.

**Output** (`src/lib/exportOutput.ts`):
- PNG — SVG → blob URL → `<img>` → canvas → `toBlob`. `effectiveScale` steps the requested 1x/2x/3x down when it would exceed the browser canvas dimension/area caps.
- PDF — no PDF library. `printPages` writes an off-screen iframe with `@page` sized to the chosen paper and calls `print()`; the user picks "Save as PDF" (vector, selectable text).
- `buildPages(rows, opts, geom, multipage, perSection)` splits row-outer / date-inner. Vertical slices come from `paginateRows` (pure, greedy by row height; a section header never ends a page, a page starting mid-section opens with the header again as `cont`, `breakPerSection` starts each section on a new page), horizontal slices from `dateSlices` (greedy, cut on unit boundaries). Each page is a fresh `buildGanttSvg` call on a row+date subset, so the header band and LHS columns repeat for free. With `multipage` off, one page is emitted (one per section with `perSection`) and the print CSS scales it to fit (`preserveAspectRatio="xMinYMin meet"`, never upscaled). Page labels name the sections on the page, else the task range.

**Dialog** (`src/components/ExportDialog.tsx`): `source` is `{ kind: 'board', tasks, allTasks }` (App header) or `{ kind: 'sections', rows, depths, critical, unit, criticalOn, today }` (portfolio Gantt tab: the Tasks group and the critical scope are hidden, unit / critical start from the tab and are not persisted, PDF adds "Each project on its own page" = `pagePerSection`). Board mode: format, task scope (visible / all / manual pick), dateless toggle, time period (fit / custom via the existing `DatePicker`), left columns, unit (auto/day/week/month), arrows + today + critical path (with its own project/exported scope) + title, then paper/orientation/`Allow multiple pages` (PDF) or scale (PNG). Live preview re-runs the pure builder in a `useMemo`. Options persist to `localStorage['gantt-export-opts']` (dates and manual picks excluded).

## ClickUp pull / push

App talks to ClickUp REST API directly from browser. No backend — all sync logic client-side.

**Network path**: nginx proxies `/clickup/*` → `https://api.clickup.com/api/v2/*` (`nginx.conf` `location /clickup/` block). `resolver` directive required for nginx-alpine to resolve `api.clickup.com` at runtime; `proxy_ssl_server_name on` required for SNI. `vite.config.ts` mirrors proxy under `server.proxy` for parity in `vite dev`. Personal API tokens (`pk_*`) sent in `Authorization` header verbatim, no `Bearer ` prefix (OAuth would need it; not used).

**Config** (`src/hooks/useClickUpConfig.ts`): `ClickUpConfig` (`token`, `teamId`, `spaceId`, `folder`, `listId`, optional `lastSyncAt` = last successful pull or push, the fallback baseline of the conflict check for tasks without a `syncBase`) persisted to `localStorage['clickup-config']`. `folder` is real folder id or literal `'folderless'` for spaces with lists directly under space. Token in localStorage — acceptable for personal tool but readable by XSS (noted in `ClickUpSettings.tsx`).

**Settings UI** (`components/ClickUpSettings.tsx`): cascading dropdowns Workspace → Space → Folder → List. Token entry has explicit "Load" button to avoid firing requests on every keystroke. Mounted from "ClickUp" button in `App.tsx` header.

**API client** (`src/lib/clickup.ts`): pure functions over `fetch('/clickup/...')`. Tokens passed as first arg; nothing module-scoped. Throws `ClickUpError` (status + body) on non-2xx. `toClickUpDate`/`fromClickUpDate` translate between JS `Date` and ClickUp's "ms since epoch as STRING"; `fromClickUpDate` returns `Date | null`. `getAllTasks` paginates until page returns < 100 tasks. `CreateTaskBody` omits date fields entirely when a task has no dates and takes `parent` to create a subtask; `UpdateTaskBody` accepts `start_date?: string | null` and `due_date?: string | null` — sending `null` clears the date in ClickUp. `listTeamMembers` fetches via `GET /team` (not `/team/{id}/member` — that endpoint doesn't exist). `getListStatuses(token, listId)` returns `ClickUpStatus[]` (`{ status, color, orderindex }`). `addTagToTask`/`removeTagFromTask` use `POST /task/{id}/tag/{name}` and `DELETE /task/{id}/tag/{name}`. `addDependency` / `removeDependency` use `POST /task/{id}/dependency` and `DELETE /task/{id}/dependency?depends_on=&dependency_of=`. `deleteTask` uses `DELETE /task/{id}` (ClickUp deletes the subtasks with it); only the confirmed push deletions call it.

**Remote -> local mapping** (`src/lib/sync.ts`, `mapRemoteTask(r, id)`): the one place a `RemoteTask` becomes a `GanttTask` (milestone collapse, priority, status + status type, estimate). Used by pull (new rows and the pull target of linked rows) and by the portfolio fetch. Dependencies are left to the caller.

**Two one-way operations** (`src/lib/sync.ts`), header buttons "↓ Pull" / "↑ Push" in `App.tsx`. No merge: each one names its winner. The caller fetches the list (`getAllTasks`, fatal on failure), runs `findConflicts`, lets the user resolve them when there are any (`SyncConflictDialog`), on a push asks about every pending deletion (`SyncDeleteDialog`), then applies with the resulting `Overrides` and decisions. The held state is one `pendingSync` object in `App.tsx` (`stage: 'conflicts' | 'deletions'`).
- `pullFromClickUp(local, remote, overrides?, pending?) -> { tasks, entries }`, **pure**, ClickUp wins, nothing written to ClickUp. Linked rows take the ClickUp fields (`pullTarget`: `mapRemoteTask` over the local row; a missing remote description keeps the local one; a null remote date clears the local one), rows deleted in ClickUp go, ClickUp-only tasks are added (new rows last, topo order) except the cuids in `pending` (pending deletions, one `info` note), board-only rows are left alone. Hierarchy: every linked row takes its ClickUp parent and `remoteParent`; a parent outside the list leaves it at the top level. Dependencies of linked rows **mirror** ClickUp, except edges to board-only rows, which stay. Orphaned `parentId`s are cleared. Overrides (fields, parent, dep edges) replace what ClickUp would set, but `syncBase` always records **ClickUp's** state, so a value kept / merged / edited on the board is a board edit the next push sends without asking. App applies `tasks` with one `setTasks`.
- `pushToClickUp(config, local, remote, overrides?, deletions?) -> { patches, entries, latestUpdate, settled }`, board wins. Overrides are applied to the board rows first (`applyOverride`) and also returned as board patches, so both sides end with the decided values. Linked rows: PUT **only the changed fields** (tags via add/remove calls; `custom_item_id` only on a real type flip); a linked row whose ClickUp task is gone is skipped, never recreated. Board-only rows are created parents first, with `parent` when the parent's cuid is known. Parents: local != remote -> `PUT { parent }`; local top level vs remote subtask in the list -> error entry (`TOP_LEVEL_BLOCKED`), never `null`; parent outside the list -> untouched. Dependencies **mirror** the board: missing edges POSTed, ClickUp edges between two board tasks that the board lacks DELETEd, edges to tasks not on the board untouched. The board only gets `patches` (new `clickupId`, `remoteParent` / `syncBase` baselines, override values), applied by id with a functional `setTasks`, so edits made during the push survive. Confirmed deletions run **last** (see Deleting tasks).
- **Field diff** (`diffFields`, table `FIELDS`): name, type, start, due, status, priority, assignees (sorted ids, sentinel `-1` excluded), tags (sorted names, `\n`-joined so a base can be split back), description, estimate, compared as strings; dates **by day** (`fmtDate`), so frappe's 23:59:59 ends or ClickUp's 4 am due dates never count as a change. `pushDiff` drops the estimate (pull-only) and a status / priority / description the board never had (undefined), so they are not re-pushed forever.
- **Sync base** (`syncBaseOf` in `sync.ts`): per linked task, `SyncBase` = `FIELDS` comparison strings of the agreed state (estimate excluded; description as an FNV-1a `hashText` to keep storage small) + `deps` (sorted predecessor cuids). Written by pull (ClickUp's state) and push (ClickUp after the writes: pushed fields from the board, the rest from ClickUp; a failed update keeps the old field prints; deps = ClickUp's edges after the adds / removes; created tasks: what was sent, ClickUp's default status). A missing key means unknown.
- **Conflicts** (`src/lib/conflicts.ts`, pure): `findConflicts(direction, local, remote, lastSyncMs)` -> `SyncConflict[]`, one per field / parent / dependency edge. With a base it is three-way: pull flags fields the board changed (`fieldPrint !== base`), push fields ClickUp changed; `both` marks ones changed on both sides; the same value on both sides is no conflict. Without a base, the old whole-task rule: pull = differs while ClickUp's `date_updated` is not newer than `lastSyncAt` (nothing before the first sync), push = differs while it is newer. Pull never counts a field the board never had (`boardLacks`, same rule as `pushDiff`); two milestones only get a `Due` conflict. Parent uses `remoteParent` (pull: board moved and differs; push: ClickUp moved and the board's parent is a pushable cuid). Dependencies: per edge between linked tasks in the symmetric difference, against `base.deps`. Tags / assignees carry `items` (union, `merged` default = three-way `mergeKeys`: kept unless a side removed it since the base, plus both sides' additions; plain union without a base); name / description carry the full `text` of each side. `resolveConflicts(direction, conflicts, picks, local, remote)` -> `{ overrides, log }`: `Resolution` is `board | clickup | merge (keys) | edit (text)`; picking the run's own winner adds no override; status copies color + type (`FIELD_PROPS` / `copyFields`); merged tags keep ClickUp's colors, `-1` assignees stay; an empty edited name falls back to the board's. Log: one `resolved` entry per task (`resolved: { field, board, clickup, result, how }[]`), plus an `info` note on a pull that kept board values.
- **`SyncConflictDialog`**: grouped by task, per conflict a radio row of value cards Board / ClickUp (+ Merge checklist for sets, + Edit input / textarea for name / description, prefilled from the side picked so far, with "start from board / ClickUp / both"), badge (changed on both sides / on the board / in ClickUp), "Use for all" Board / ClickUp, defaults = the run's winner. Cancel changes nothing. After applying, `lastSyncAt = max(now, newest date_updated seen)` (pull: whole list, push: write responses), so a client clock behind ClickUp's does not flag the tasks just written.

**Deleting tasks** (`src/lib/deletions.ts`, pure, tested): a board delete never touches ClickUp by itself. `removeTask` stores a `PendingDeletion { id, deletedAt, index, tasks }` (snapshot of the removed rows, root first) in `localStorage['gantt-pending-deletions']` when the subtree holds a linked task (`recordDeletion`; unlinked deletes record nothing; `clearTasks` is a local reset and clears the list).
- Header chip "🗑 N pending deletions" opens `PendingDeletionsDialog`: Restore (one / all, newest first) splices the snapshot back at `index` (`restoreDeletion`, skips rows already on the board by id or cuid). Rows that still depend on a deleted id get their arrows back, since `removeSubtree` leaves dependency ids alone.
- Every pull / push first drops pending deletions with no linked cuid left in the fetched list (`prunePending`). Pull keeps the rest off the board.
- Push: `planDeletions(pending, board, remote)` -> one `DeletionCandidate` per pending deletion still in ClickUp, oldest first: `deleteCuids` = its topmost tasks, `doomed` = what ClickUp deletes with them, `extra` = doomed tasks that are not pending (still on the board / only in ClickUp, shown as a warning), `changedInClickUp` (`date_updated` after the delete). The hierarchy is ClickUp's **after this push's moves**: a board row under a linked board parent escapes, a board top-level row stays under its ClickUp parent (`TOP_LEVEL_BLOCKED`). `SyncDeleteDialog` asks one at a time: Cancel push (nothing written) / Keep in ClickUp / Delete in ClickUp / Keep this and N more / Delete this and N more; it opens after the conflict dialog when both apply.
- In `pushToClickUp` the deletes run after every other write, so moved subtasks are out first. A cuid already inside a subtree deleted in the same run is skipped; a 404 counts as gone. Kept -> `skipped` entry ("Pull brings it back"); deleted -> `deleted` entry; a failed delete -> `error` and the deletion stays pending. `settled` (kept + deleted) is dropped from the pending list.

**Sync log**: every pull / push returns `SyncLogEntry[]` (`types.ts`: kind `updated | added | removed | deleted | created | moved | dep-added | dep-removed | skipped | resolved | info | error`, task name / local id / cuid, `changes: { field, from, to }` with from = old value at the destination, `resolved` for conflict decisions, `detail`). `src/hooks/useSyncLog.ts` keeps the last 20 `SyncReport`s in `localStorage['gantt-sync-log']` (memory only on quota), each capped to 500 entries by `capRun` (errors kept). A failed fetch is logged as a run with `aborted`. Header chip = `runSummary` of the latest run (red on errors), click opens `SyncLogDialog` (runs newest first, entries grouped by `KIND_ORDER`, field change tables, task names open the task popup). Helpers in `src/lib/syncLog.ts`.

**Pull-only fields**: `statusType` and `timeEstimate` follow ClickUp on every pull; push never sends or touches them.

**Synced fields**: `name`, `start`/`end` dates (optional; null/undefined preserved), `dependencies`, `priority` (push+pull; ClickUp int 1–4), `description` (push+pull), `assignees` (push+pull; push sends `{ add: [...ids], rem: [...ids] }` diff; sentinel id `-1` excluded), `status` (push+pull), `tags` (push+pull; per-tag add/remove via tag name), `type` (push+pull via `custom_item_id`; `MILESTONE_ITEM_ID = 1` in `clickup.ts`). `custom_item_id` is only sent when the type actually flips, so other custom task types in the workspace are never overwritten; a remote milestone collapses `start`/`end` onto its due date. Milestone pushes fail if the space has the Milestones ClickApp disabled — the error lands in the run's log as an `error` entry.

**Limitations**: tasks without a `syncBase` (data from before it, until their next pull / push) fall back to the whole-task `lastSyncAt` rule, which misses edits made on both sides; a local delete reaches ClickUp only through a confirmed push; no rate-limit backoff (ClickUp free tier ~100 req/min — surface 429s, retry manually); no realtime/webhook/auto-poll. Comments, attachments, time tracking, `progress` not synced. Subtask -> top-level is not possible through the API (see Subtasks).

**Hook contract** (`src/hooks/useTasks.ts`): raw `useState` setter exposed as `setTasks` so a pull does a single bulk replacement and a push patches by id. Persistence `useEffect` watches `tasks`, writes `localStorage['gantt-tasks']`; bulk replacement round-trips through JSON serialize/deserialize cleanly (dates → ISO string → Date; undefined dates → field absent in JSON → undefined on deserialize).

## Portfolio (multi-project, read only)

Directors' view over several ClickUp lists; **one list = one project**. Nothing in it writes to ClickUp: the fetch only issues GETs, and editing stays on the board.

**Data** (`src/lib/portfolioData.ts`): `ProjectRef { listId, name, folderName?, spaceName? }`, `PortfolioTask = GanttTask & { projectId, warningIds }`, `PortfolioProject { ref, color, tasks, isCurrentBoard, fetchedAt?, error? }`. `toPortfolioTask` = `mapRemoteTask(r, r.id)` + `parentId` + `dependencies` (`remotePreds`; lists cached before that carry none until their next Refresh) + `warningIds` from `contentWarningIds` (description facts with the DoD keywords of that moment, independent of the warning toggles), then `description` is dropped to keep the cache small (so description checks must be precomputed, never derived from cached tasks; keyword edits reach cached lists on their next Refresh). `fetchProjects(token, listIds, onProgress, dodKeywords)` runs `getAllTasks` with a pool of 3; a failing list (429 included) yields its own `error` and never aborts the others. `demoProjects(today)` is a synthetic red / amber / green / done portfolio with one person over capacity this week, used by the in-memory "Load demo data" button and by tests.

**Colors**: `PROJECT_COLORS` is a fixed, CVD-validated categorical order (dataviz reference palette); a project's slot is its position in the picked list, so a color follows the project, never its rank. Past eight projects use `OTHER_COLOR` and fold into "Other" in stacked charts. Status colors (good `#0ca30c`, warning `#fab219`, critical `#d03b3b`, as `--pf-*` vars in `Portfolio.css`) are reserved for state and always paired with an icon / label.

**State** (`src/hooks/usePortfolio.ts`, called in `App.tsx` so it survives view switches): `localStorage['portfolio-config'] = { refs, hidden }` and `localStorage['portfolio-cache'] = { [listId]: { fetchedAt?, error?, tasks } }` (quota failure -> kept in memory, notice shown). The list linked to the board (`config.listId`) is never fetched: it is replaced by the live board tasks, unsynced edits included. No refs picked -> the board alone as "Current board" (also the no-ClickUp case). `missing` = picked lists with no cache entry; `PortfolioView` auto-fetches those. A failed refresh keeps the last good tasks with the error attached.

**Rules** (`src/lib/portfolio.ts`, pure, every date function takes `today`):
- `isDone`: `statusType` closed / done; without a type, status-name regex fallback.
- `isOverdue`: open, `end` before today. `isLateStart`: open, not a milestone, `start` before today, still in initial status (`statusType === 'open'`, or a to-do-like name). `isDueSoon`: due today .. +`Settings.rules.dueSoonDays` (7).
- RAG (`projectHealth(tasks, today, settings)`, thresholds in `Settings.rules`): **red** = an overdue milestone, or project end passed with open tasks, or >= 20% of open tasks overdue; **amber** = any overdue / late start, or >= 25% of open tasks undated; else **green**; no open tasks = **done**. `ragReasons` feed the pill tooltip.
- `riskItems`: open tasks with any risk kind, worst kind first, then days late. `riskLabel(kind, settings)` names the kinds (due-soon shows the configured days).
- Both drop backlog tasks first when `include.health` is off; quality = `applyWarningSettings(t.warningIds ?? [], t, settings)` non-empty.

**Workload** (`src/lib/workload.ts`, `computeWorkload(tasks, boundaries, { metric, keysOf, includeDone, workdays })`): buckets come as n + 1 boundaries, so the portfolio (`unitBoundaries`) and the board strip (frappe columns) share one engine. Milestones skipped; undated -> `skippedUndated`; done excluded unless `includeDone`. `count`: +1 per key in every overlapped bucket. `hours`: `timeEstimate` spread evenly over the task's working days (`workdays`, Mon-Fri by default; all days for a task with none), split evenly across keys; no estimate -> `missingEstimate`, contributes 0. `items` per bucket drive the click drill-downs. Portfolio callers pass project-qualified ids (`${projectId}:${id}`) because ids are only unique within a list. Callers drop backlog tasks themselves (`withoutBacklog(tasks, settings, 'workload')`).

**Views** (`src/components/portfolio/`, styles in `Portfolio.css`):
- `PortfolioView`: tabs, Projects picker / Refresh / fetched stamp, per-project visibility chips, banners (no ClickUp, nothing picked, quota, per-list errors). `today` is fixed per mount so every tab agrees.
- `OverviewTab`: KPI tiles, sortable health table (row click filters the risk list), risk list with kind chips (default overdue / late start / due soon), capped at 200 rows.
- `RoadmapTab`: single scroll box, sticky header row + sticky LHS; project bar = `projectSpan`, done share as darker fill, red outline when RAG red, milestone diamonds, today line; rows expand into dated tasks + an undated count.
- `GanttTab`: read-only multi-project gantt, one section per visible project, drawn by the export renderer so Export (sections source) prints the same chart. Rows from `portfolioGanttRows(projects, today, settings, { subtasks, includeDone, includeDateless, order, collapsed })` in `src/lib/portfolioGantt.ts` (pure, tested): backlog dropped per `include.board`, ids / parents / dependencies qualified `${listId}:${id}`, siblings by start date (undated last) or list order, filtered tasks keep their ancestors (`flattenTree` include), top level only = roots with anything kept below; section summary from `projectHealth` (same numbers as the Roadmap bar). `portfolioCritical` = each project's own chain, unioned. Prefs in `localStorage['portfolio-gantt']` (unit, order, subtasks, done, dateless, critical, collapsed project ids). Pinned date header and names column are zero-height `position: sticky` copies of the chart through `<use href="#pf-gantt-chart">`; since a click there lands on the `<use>`, a click is mapped to its row by y position (click a project row = fold it). Its card stays white: the chart colours are the export's literals.
- `WorkloadTab`: metric / unit / scope (all projects stacked by project with a "Projects" active-count band, or one project stacked by person, top 7 + Other) / range presets / include done. `StackedBarChart` is hand-written SVG (bars <= 24px, 4px rounded data end, 2px surface gap between segments, hit target = whole slot).
- `PeopleTab`: person x bucket heatmap over all visible projects; sequential blue ramp by share of capacity, critical + "!" when over (hours: capacity h/day x workdays in bucket; count: max tasks per period). Unassigned row last, neutral.
- `ProjectPicker`: Space > Folder > List tree with search (`listSpaces`, `listFolders` (its response embeds `lists`), `listFolderlessLists`); saving keeps the existing order and appends new picks, since order decides color.
